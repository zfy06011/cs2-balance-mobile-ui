# 数据调用链路 —— 库存 / Steam 历史 / C5 历史

> 配套《软件介绍.md》。本文回答：**App 内「库存同步」「Steam 历史」「C5 历史」分别调用哪些接口、带什么凭证、数据落到哪里、又被谁消费。**
> 代码位置：`mobile/src/data/`（接口适配层）、`mobile/src/core/`（引擎组合层）、`mobile/src/screens/`（UI 层）。

## 0. 总览

```
┌─────────────┐   ┌────────────────────┐   ┌─────────────────┐   ┌──────────────┐
│  UI 层       │ → │ 引擎层 engine.ts    │ → │ 适配层 data/*    │ → │ 外部接口      │
│  Screens     │   │ 组合/入库/诊断       │   │ steam.ts c5.ts  │   │ Steam / C5   │
└─────────────┘   └────────────────────┘   └─────────────────┘   └──────────────┘
                          │
                          ▼
                本地快照库 storage.ts（AsyncStorage）
                来源标记 source: 'steam' | 'c5' | 'c5_hist'
                实时快照保留 50 条、历史日线保留 120 条（HISTORY_KEEP）
```

统一数据模型 `LocalSnapshot`：`{ name, source, price, volume, fetchedAt }`，快照库键 `@cs2balance/snapshots_v2`。
> **v1.5.10 新增**：历史价格主通道改为「云端历史」（`cloud/` Cloudflare Worker + D1，Steam 官方 gid 页 SSR 数据，零登录）；详见[第 6 章](#6-云端历史cloudv1510-新增主通道)。

## 1. 库存同步（C5 OpenAPI app-key 唯一通道）

> 用户已拍板（v1.5.9 方向变更）：**库存只用 C5GAME 官方 OpenAPI（app-key）**，Steam Web API 库存方式已整体移除。
> 原因：Steam Web API 对交易保护期账号返回 `{"response":{}}`（v1.5.7 用户实测双 context 全空）；C5 服务端高权限通道能看到 status=4 保护中物品。

### 1.1 调用链

```
库存页 InventoryScreen
  └─ api.syncSteamInventorySmart()                     // mobile/src/api/client.ts
      └─ engine.syncSteamInventorySmart()              // mobile/src/core/engine.ts
          ├─ 读设置：c5AppKey / steamId
          ├─ 若 steamId 为空且做过 Steam 一键登录：resolveOwnSteamId(steamCookie)
          │        // steamcommunity.com/my 解析本人 ID（仅用于识别 ID，库存不依赖 Steam cookie）
          └─ fetchC5Inventory(steamId, c5AppKey)               // data/c5.ts
              ├─ GET openapi.c5game.com/merchant/inventory/v2/{steamId}/730
              │      ?language=zh&startAssetId=<lastAssetId>&app-key=<key>
              ├─ 自动分页直到 data.lastAssetId 为空（最多 20 页）
              └─ parseC5Inventory() + aggregateC5Inventory()
                  // 武器箱过滤（marketHashName 含 case/package/武器箱/胶囊/收藏包）
                  // status=4 冷却中 → tradable=false；status=0/1/7 → tradable=true
                  // 同 marketHashName 多资产聚合（数量求和、可交易取或）
      └─ planSteamSync()                               // core/steamSync.ts（纯函数）
          ├─ 按英文 MarketHashName + C5 中文名双键匹配本地库存
          ├─ C5 有而本地无 → 自动导入（source='steam_sync'，buy_price=0）
          ├─ 冷却估算：已解锁记「观察到可交易」时刻；冷却中取 min(历史估计, 本次观察+剩余整天)
          └─ 空库存 → buildC5EmptySyncReason() 生成中文诊断
              // C5 返回空 = SteamID64 非本人 / C5 app-key 未绑定该账号，不再有保护期歧义
      └─ storage 写入库存表 / 返回 { matched, imported, notFound, empty, reason, ... }
```

### 1.2 依赖与凭证

- **必须**：C5GAME app-key（免费申请：opendoc.c5game.com；库存与价格统一走它）
- **必须**：SteamID64（17 位数字 / profiles/ 链接；做过 Steam 一键登录可自动识别本人 ID）
- 可选：Steam 登录 cookie（仅自动识别本人 SteamID64，不再参与库存拉取）

### 1.3 关键事实

- C5 库存接口能看到交易保护期物品（`status=4` 暂时不可交易/冷却中，归为 `tradable=false`；
  0 正常 / 1 在售 / 7 可出租为可交易）→ **彻底解决 Web API 时代「保护期空库存」问题**
- 分页：响应 `data.lastAssetId` 非 null 时作为下一页 `startAssetId`，直到为 null
- 返回空（`data.list` 空）时的诊断：C5 服务端未见任何物品 → 核对 SteamID64 是否本人、C5 app-key 是否绑定该账号
- Steam Web API 库存（IEconService 双 Context）、设置页 Steam Web Key 输入项已于 v1.5.9 移除

## 2. Steam 历史（两个来源，一条存储）

### 2.1 来源 A：实时采集快照累积（自动，无需登录）

```
首页「📡 一键扫描」→ engine.refresh() → collector.collectCases()
  ├─ searchCases()   // steamcommunity.com/market/search/render/?sort_column=popular|volume&l=schinese
  │                   // 拿热门武器箱 + 官方中文名（缓存到 zhNames）
  ├─ fetchC5PricesBulk()   // C5 OpenAPI 买入价（见第 4 章）
  └─ 逐个 fetchSteamPrice()  // steamcommunity.com/market/priceoverview/?appid=730&currency=23&market_hash_name=..
      └─ storage.setSnapshot({ source: 'steam', fetchedAt: 真实时间戳 })
```

- 每次扫描产生一个「当日实时点」；实时快照每箱最多保留 50 条（STEAM_KEEP）
- 消费方：`getSteamPrices()`（预测器输入）、`getSteamHistory()`（趋势图、成交量历史）

### 2.2 来源 B：官方历史日线补录（一次补 120 天）

- **v1.5.10 主通道（云端，零登录）**：见[第 6 章](#6-云端历史cloudv1510-新增主通道)——`GET <Worker>/history?name=..&days=120` → `storage.mergeSteamHistory()` 入库
- 旧通道（保留代码，无主入口）：`CookieLoginScreen` 旧 `steam-hist` 在 Steam 页面内抓取 `var line1=[...]` / `queryData.prices`
  → `api.importSteamPriceHistoryRaw(name, prices)` → `storage.mergeSteamHistory()`
- 该通道需有效 Steam 登录 cookie：`steamcommunity.com/market/pricehistory/` 未登录返回 400/401；
  列表页 HTML 抓取实测在该类网络环境 0 成功 → **v1.5.5 起主入口切换到 C5 官方趋势通道**（见第 3 章），
  Steam 历史仍可依赖「来源 A」实时快照累积

### 2.3 入库规则（mergeSteamHistory）

- 按日期去重（同一天重复导入只算一次）；历史点 `fetchedAt = 日期 T08:00:00.000Z`（与实时快照可区分）
- 每箱最多保留 120 条历史日线（HISTORY_KEEP），超限截断最旧
- 入库后预测器 / 雷达 / 详情趋势图自动受益（它们只读快照库，不关心数据来源）

## 3. C5 历史快速导入（v1.5.5 主通道）

### 3.1 为什么用 C5

- Steam `pricehistory` 需登录 cookie 且该网络环境不稳定（实测 0 成功）
- **C5GAME 网页有官方趋势图接口**（已实测可用），带 C5 登录 cookie 即可返回 90 天价格走势——
  恰好复用 v1.5.4 修好的一键登录 cookie。

### 3.2 调用链

```
首页「🔁 快速导入历史（C5 官方趋势）」
  └─ CookieLoginScreen（kind='steam-hist'，WebView 改为打开 C5 官网）
      ├─ 一键登录 C5 → 自动保存 c5Cookie（原生 CookieManager + document.cookie 双通道）
      └─ 右上角「开始导入」→ engine.startHistPull 逻辑（CookieLoginScreen.tsx）
          ├─ 读设置 c5AppKey / c5Cookie；无 c5Cookie → 提示先登录，不发请求
          ├─ api.c5HistoryTargets(60)     // Steam/C5 历史点不足 14 的箱子优先，升序
          └─ api.importC5Histories(names, {c5AppKey, c5Cookie}, onItem, startIdx)
              └─ engine.importC5Histories()                 // core/engine.ts
                  for 每箱：
                    1) 查 itemId：
                       a) 有 app-key → POST openapi.c5game.com/merchant/market/v2/
                          item/stat/hash/name   {appId:'730', marketHashNames:[name]}
                          → 响应里 itemId（顺便拿到求购最高价，供「卖出参考」）
                       b) 没有/失败 → GET www.c5game.com/steamtrade/sga/item-search/v1/list
                          ?appId=730&keyword=<名>   （需 c5Cookie）→ 弹性提取 itemId
                    2) 拉趋势：GET www.c5game.com/trade-flex/order/price-trend/chart
                          ?itemId=<id>&period=90   （需 c5Cookie）
                          → parseC5Trend() 弹性解析内嵌 { dates:[unix秒], prices:[元] } → 取最近 120 天
                    3) 入库：storage.mergeC5History(name, pts)
                          → source='c5_hist'，按日期去重，最多保留 120 条
                 失败处理：任一件失败立即停止返回 {failedIdx, failedName, failedReason}
                  → UI 弹窗「停止 / 跳过此箱继续」（跳过则从 failedIdx+1 重新调用），
                    不再静默跳过；进度实时显示「done/total」
```

### 3.3 消费方

- `storage.getC5History(name)` → `engine.c5BuyAdvice(name)`：近 7/30 天 C5 历史统计 + 近 24h 变化 + 分位 + 趋势（买入时机参考）
- C5 历史独立于 Steam 历史存储（`source='c5_hist'`），不会污染 Steam 预测输入；预测器只读 `source='steam'` 数据

## 4. 附：C5 实时买入价（采集阶段）

```
collector.collectCases（一键扫描）
  └─ fetchC5PricesBulk(names, c5AppKey)      // 需 C5 app-key
      └─ POST openapi.c5game.com/merchant/product/price/batch?app-key=..
          body: { appId:'730', marketHashNames:[...] }   // 每批 ≤30 个
      └─ storage.setC5Price(name, price)     // source='c5'，单箱只保留最新一条
```

- 无 app-key / 失败 / 无数据 → 返回 null，不臆造价格；用户可在详情页手动录入 C5 买入价兜底

## 5. 接口速查表

| 用途 | 接口 | 凭证 | 频率/限制 |
|---|---|---|---|
| Steam 实时价 | `steamcommunity.com/market/priceoverview/?appid=730&currency=23&...` | 无 | 采集间隔约 1.8s |
| Steam 热门榜/搜索 | `steamcommunity.com/market/search/render/?sort_column=popular|volume` | 无（登录更全） | 页间 1.2s |
| Steam 历史日线 | `steamcommunity.com/market/pricehistory/`（旧，需 cookie 不稳定） | Steam Cookie | 已停用为主通道 |
| C5 买入价 | `openapi.c5game.com/merchant/product/price/batch` | app-key | 50 QPS 上限 |
| C5 库存（唯一通道） | `openapi.c5game.com/merchant/inventory/v2/{steamId}/730` | app-key | 自动分页，最多 20 页 |
| C5 itemId/求购价 | `openapi.c5game.com/merchant/market/v2/item/stat/hash/name` | app-key | — |
| C5 网页搜索（查 itemId 兜底） | `www.c5game.com/steamtrade/sga/item-search/v1/list?appId=730&keyword=..` | C5 Cookie | 非官方，可能变更 |
| C5 历史趋势 | `www.c5game.com/trade-flex/order/price-trend/chart?itemId=..&period=90` | C5 Cookie | 非官方，可能变更 |

> 原则：**库存与买入价走 C5GAME 官方 OpenAPI（app-key）**；**历史价格走 C5 网页趋势接口（需 C5 登录 cookie）+ Steam pricehistory（需 Steam cookie，已降级）**；C5 网页接口仅用于「历史导入」与「itemId 兜底」，已在代码中集中隔离（`data/c5.ts`），接口变更时只需改适配层。

## 6. 云端历史（cloud/，v1.5.10 新增主通道）

> **数据源**：Steam 官方市场 gid 页 SSR 数据（`window.SSR.renderContext` 内嵌 pricehistory，**零 cookie**，
> 2013-08-14 至今全量日线 + 近期小时粒度 + 盘口深度，CS:GO Weapon Case 实测 5202 点）。
> 由 Cloudflare Worker 定时抓取缓存到 D1，App 只读拉取，**不再依赖 Steam 登录 cookie / C5 登录态**。
> 实验结论详见《Steam官方接口研究报告.md》第 9 章。

### 6.1 为什么是云端

| 通道 | 结论 |
|------|------|
| Steam `pricehistory` API | ❌ 必须登录 cookie，未登录返回 `[]`/400，云端不可用 |
| Steam 市场列表页 line1 | ⚠️ 公开可取但旧版格式，无小时粒度/盘口，数据不全 |
| **Steam gid 页 SSR（采用）** | ✅ **零 cookie 公开可取**，全量 + 盘口，Cloudflare 海外出口直连无需 Steam++ |
| C5 OpenAPI 历史 | ❌ 不存在历史端点（枚举全部文档 + 9 个疑似端点 404） |
| C5 网页趋势 | ⚠️ 必须登录 cookie（「查看价格走势请先登录」是官方设定），仅作 App 内回退通道 |

### 6.2 调用链（App 侧）

```
首页「🔁 快速导入历史（云端 / C5 官方趋势）」
  └─ CookieLoginScreen（kind='steam-hist'）
      └─ startHistPull（v1.5.10 改为云端优先）
          ├─ 读设置 cloudWorkerUrl
          ├─ 有值 → api.importCloudHistories(names, cloudUrl, onItem, startIdx)
          │     └─ engine.importCloudHistories()            // core/engine.ts
          │         for 每箱：
          │           1) fetchCloudHistory(cloudUrl, name, 120)   // data/cloudHistory.ts
          │              GET {cloudUrl}/history?name=<URL编码>&days=120
          │              → { name, price_prefix, points:[[ts秒, 价格, 成交量], ...] }
          │           2) cloudPointsToHistory(points)  // unix秒 → 'YYYY-MM-DD'（UTC）
          │           3) storage.mergeSteamHistory(name, pts)   // source='steam'，按日期去重、保留 120 条
          │         失败处理：任一件失败停止返回 {failedIdx,...}
          │          → UI 弹窗「停止 / 跳过此箱继续 / 改用 C5 官方趋势」
          └─ 未配置 cloudWorkerUrl（或全部失败时用户选择）→ 走 C5 官方趋势（见第 3 章，需 C5 登录态）
```

### 6.3 云端侧（cloud/，Cloudflare Worker + D1）

- **部署**：`cloud/` 目录（wrangler + TypeScript），`docs/HANDOFF.md` 有部署步骤
- **定时采集**：cron `*/15 * * * *`（环境变量可调）；每轮先取热门武器箱 Top-100
  （`market/search/render/?sort_column=popular&category_730_Type[]=tag_CSGO_Type_WeaponCase`），
  失败回退 D1 已有名称 / 内置兜底清单
- **解析**：`fetchListingHtml`（名称页 → 302 跟随 → gid 页）→ `parseSSR` → `extractPriceHistory`
  → 按 `history` 表 `(market_hash_name, ts)` 去重置入；gid 缓存到 `gid_map` 免重复重定向
- **公开 API**：`GET /history`（点序列）、`GET /items`（已收录列表）、`GET /health`；
  可选 `POST /ingest`（本机采集器兜底写入口，`INGEST_TOKEN` 鉴权）
- **免费额度**：Worker 10 万请求/天 + D1 5GB/10 万行写/天；初始约 50 万行 + 每天约 1 万行增量，余量充足
- **风险与兜底**：若 Steam 对数据中心 IP 风控（403/captcha），降级为「国内本机采集器（复用 Steam++ 反代）
  抓 gid 页 → POST /ingest 写 D1」，Worker 只做存储 + 读 API

### 6.4 设置与使用

- 设置页「数据源配置」新增 **云端历史地址**（如 `https://cs2-price-history.xxx.workers.dev`），可选
- 未填地址时「快速导入历史」回退 C5 官方趋势（需 C5 登录一次，行为同 v1.5.5）
- 已收录箱子：Cloudflare 海外出口直连 Steam 采集，国内 App 仅访问 Worker 地址（若 `workers.dev` 被墙，
  可绑定自定义域名后在设置页改填）
